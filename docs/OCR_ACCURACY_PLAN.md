# OCR 准确率优化计划（目标 99%）

> 端侧纯本地（CoreVisionKit textRecognition），不联网。目标：清晰扫描件字符级准确率 ≥99%，低质扫描 90%+。

## 1. 准确率如何度量
- 文字型 PDF：自带文本层即真值。渲染页面后 OCR，与文本层逐字符对比（CER=编辑距离/真值长度）→ 零成本基准集。
- 扫描件：人工校对 3–5 份样张（发票/合同/书页/表格/手写各一）作为固定回归集，每次调参复测。

## 2. 本轮已做
- 渲染 3× 高清（上限 4096px，原 2×），开启方向检测。
- 彩色 + 灰度双路：彩色结果过短（<30 字符）自动跑灰度并做行级去重合并。
- 文本归一化：去零宽字符/BOM、去中文间误插空格、压缩连续空白。
- 新增逐页 OCR 接口 ocrPdfPagesAsync（保留页序，供 PDF→Word 使用）。

## 3. 下一阶段（按收益排序）
| 阶段 | 手段 | 预期收益 | 成本 |
|---|---|---|---|
| P1 | 图像预处理：对比度/亮度增强、自适应二值化、中值去噪、去倾斜、自动裁边 | +5~15% | 中 |
| P2 | 多参数投票：2×/3×/4× + 灰度/二值/反色多路 OCR，行级编辑距离投票取一致结果 | +2~5% | 中 |
| P3 | 版面/行合并：按 y 聚类成行、x 排序，多栏与表格行列对齐，表格转 Word 表格 | 结构化准确率大幅提升 | 中高 |
| P4 | 本地 OCR 大模型（阶段 B）：PaddleOCR → ONNX → MindSpore Lite .ms（INT8 ≤8MB），替换/并行 CoreVision | 中文 +3~8%，可达 99% | 高 |
| P5 | 端侧语言模型/词表纠错（金额、日期、单号格式） | 业务字段接近 100% | 中 |

## 4. 代码位置
- entry/src/main/ets/utils/PDFOCRUtils.ets：ocrPdfPagesAsync（逐页）、recognizePageHiRes（多路）、normalizeOcrText（后处理）。
- PDF→Word：utils/WordConvertUtils.ets（无文本层时自动走逐页 OCR）。

## 5. 说明
- 99% 必须以基准集实测为准；清晰件在 3×+双路下通常 98–99%，手写/污损/复杂表格需 P1–P4 叠加。
- 若要求强约束，建议直接进入 P4（PaddleOCR → MindSpore Lite），即原规划阶段 B。
